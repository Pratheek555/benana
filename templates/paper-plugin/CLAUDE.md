# __NAME__

A Paper plugin generated by Benana Mod Studio.

**Mod:** __SUMMARY__

## Conventions

- Target Paper 1.21.4 (`paper-api 1.21.4-R0.1-SNAPSHOT`) and Java 21. No dependencies other than the Paper API.
- The main class is `dev.benana.mod.__NAME__` (see `plugin.yml`). Put additional classes in `dev.benana.mod`.
- Build with `mvn -q package`. The jar must end up at `target/__NAME__.jar`.
- Log meaningful actions with `getLogger().info(...)`. The playtester reads the server console.
- `playtest/` holds the test plan and verdicts from Benana's in-game playtester. Read it, but don't edit it.
- Don't commit; Benana commits each attempt.

## Assets: you design the mod's art

The mod ships a resource pack from `pack/`. Benana zips it after the build and the server offers it to every player,
so custom items look like what they are. Give every custom item its own texture.

1. Draw it as pixel art in `art/<name>.json` (16x16, or 32x32 for detailed items). See the header of `tools/texture.cjs`
   for the format. Use a dark outline, 3-5 shades per material, a light source from the top left, and a transparent background.
2. Run `node tools/texture.cjs`. It writes the texture, model and item definition into `pack/assets/benana/`.
3. Read `preview/<name>.png` to look at the result, and redraw until it reads clearly as the item.
4. Point the item at it in code: `meta.setItemModel(new NamespacedKey("benana", "<name>"))`.

Pick the base `Material` for its behavior, not its look: the texture replaces the look. Use a material with no right-click
action of its own (`ECHO_SHARD`, `AMETHYST_SHARD`, `HEART_OF_THE_SEA`, `BLAZE_ROD`, `STICK`) unless the vanilla
behavior is wanted. Avoid blocks (they get placed), food (it gets eaten), bows, and throwables.

## Paper 1.21.4 cookbook

Names changed in 1.20.5-1.21.3, and old tutorials are wrong. When unsure, check the API jar rather than guessing:

```sh
JAR=$(ls ~/.m2/repository/io/papermc/paper/paper-api/1.21.4-R0.1-SNAPSHOT/paper-api-*.jar | grep -v sources | head -1)
javap -cp "$JAR" org.bukkit.Particle | grep -i dust
```

- Renamed: `Attribute.MAX_HEALTH` (not `GENERIC_MAX_HEALTH`), `PotionEffectType.JUMP_BOOST`, `SLOWNESS`, `STRENGTH`,
  `Particle.EXPLOSION`, `DUST` (needs `new Particle.DustOptions(Color, size)`), `WITCH`, `HAPPY_VILLAGER`, `FIREWORK`,
  `Enchantment.SHARPNESS`.
- **Custom items**: build with `ItemStack#editMeta`. Name with Adventure, `meta.displayName(Component.text("Storm Core",
  NamedTextColor.AQUA).decoration(TextDecoration.ITALIC, false))`. Tag it with the `PersistentDataContainer` and identify
  it by that tag, never by display name or material.
- **Right-click**: `PlayerInteractEvent` fires once per hand. Return unless `e.getHand() == EquipmentSlot.HAND`, then check
  `e.getAction().isRightClick()`. Clicking a mob fires `PlayerInteractEntityEvent` instead (same hand check). Use
  `player.getTargetBlockExact(range)` or `player.rayTraceBlocks(range)` for "the block the player looks at".
- **Velocity on hit**: vanilla knockback is applied after `EntityDamageByEntityEvent` and overwrites `setVelocity` made in
  the handler. Set velocity one tick later: `Bukkit.getScheduler().runTask(this, () -> target.setVelocity(v))`.
- **Launching players** works the same way: `player.setVelocity(new Vector(0, 1.4, 0))` (about 1.0+ is a real launch,
  a normal jump is 0.42). Cancel fall damage with `EntityDamageEvent` where `getCause() == DamageCause.FALL`.
- **Cooldowns**: a `Map<UUID, Long>` of `System.currentTimeMillis()`. Tell the player with
  `player.sendActionBar(Component.text("Recharging 1.2s"))` and log it.
- **Commands**: declare them in `plugin.yml` under `commands:` with no `permission`, so any player (the test bot is not op)
  can run them, and register with `getCommand("name").setExecutor(...)`.
- **Custom mobs and bosses**: `world.spawn(loc, IronGolem.class, g -> { ... })`. Inside, set `customName(...)`,
  `setCustomNameVisible(true)`, `getAttribute(Attribute.MAX_HEALTH).setBaseValue(200)`, then `setHealth(200)`, and
  `setPersistent(true)`. Keep its `UUID` and drive abilities from one `runTaskTimer` that cancels itself when the mob is
  dead or invalid. Check phase thresholds against `getHealth()` inside that timer as well as in damage events, so health
  set by commands is noticed too.
- **Boss bars**: `BossBar bar = BossBar.bossBar(title, 1f, BossBar.Color.PURPLE, BossBar.Overlay.PROGRESS)`. Show it with
  `player.showBossBar(bar)` to players near the boss (in the timer), update `bar.progress(health / max)` and
  `bar.color(...)`, and hide it from everyone when the boss dies and in `onDisable`.
- **Drops**: `EntityDeathEvent#getDrops().add(item)` (also fires for `/kill`). Give items with
  `player.getInventory().addItem(item)` and drop whatever does not fit.
- **Effects**: `player.addPotionEffect(new PotionEffect(PotionEffectType.JUMP_BOOST, 200, 1))`, where 200 is ticks and
  1 means level II.
- **Nearby entities**: `world.getNearbyEntities(loc, r, r, r)` or `loc.getNearbyPlayers(r)`.
- Never block the main thread. Use the scheduler for anything delayed or repeated, and cancel tasks in `onDisable`.
